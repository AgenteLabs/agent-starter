**The scaffolder for a starter agent on the FlashyOS mesh.**

`npx @flashyos/create-mesh-agent` will write a new agent's starting point — a package manifest, an `@flashyos/agent` SDK import, a charter stub naming an accountable human, and the handshake file a mesh org serves at `/.well-known/flashyos.json` — so the first thing a new agent does is exist in a form the mesh can check, rather than a blank directory and a blog post explaining what to copy.

> **Not released yet.** Carried out of a private monorepo with its real history, which is a decision rather than a build.
>
> Everything below is the design and the reasoning. The code lands before
> this repository is tagged, and the version stays at 0.0.0 until it does.

## Using it

> **Planned — not present until the generator package is migrated.** The
> `templates/`, `src/` and `bin/` trees the commands below read do **not**
> exist in this repository yet, so nothing in this section is runnable today.
> Carrying the package out of the monorepo, with its real history, is the
> gating step — see [Status](#status). This section describes how the

The design is a single command that writes a working starting point, with nothing hosted and nothing phoned home for:

<!-- planned -->
```bash
npx @flashyos/create-mesh-agent my-agent
cd my-agent
npm test
```

or from a clone, once the package has landed:

<!-- planned -->
```bash
git clone https://github.com/AgenteLabs/agent-starter && cd agent-starter
node bin/create-mesh-agent.mjs my-agent --role worker
```

## The invariants

Everything here follows from these. Each is enforced by something rather
than promised, because a rule with nothing behind it erodes one
convenience at a time.

| Invariant | Why | Enforced by |
| --- | --- | --- |
| **The scaffold must build the day it is written** | A starter that does not typecheck teaches the mesh's newest participant that nothing here works | The generator's own test runs `npm ci && npm test` inside every fixture it writes |
| **AGENT is not constructible** | The work layer's actor is a `Node`, never a bare agent — an agent acts *for* somebody and the somebody answers | The scaffold writes a charter naming a `person/` or `org/` accountable human; there is no template path that omits one |
| **Nothing is written without being asked for** | A generator a person cannot read before it runs is one they cannot trust | `--dry-run` prints every file it would write and writes nothing |
| **A re-run never overwrites unseen edits** | Silent clobbering here is the same failure shape as a sealed record edited in place elsewhere in this estate | An existing file with local changes refuses the write and names the file |

## It works alone

No account, no API key, no telemetry, and no network call unless you ask
for one — publishing the generated agent's handshake is a decision the person
who ran the command makes, never one this tool makes for them. If anything
here ever needs a service of ours to answer, that is a bug — you would be
right to refuse a scaffolder with a dependency on the mesh it is onboarding
you onto. That applies to the documentation too: the design is that every
documented command runs from your own shell against files in your own
directory, never our domain. The commands that will do so are marked
*planned* above, because the files they read do not land until the package
migrates — a README that claimed they ran today would be committing exactly
the sin this paragraph names.

## What create-mesh-agent is not

- **Not `create-mesh-node`.** `@flashyos/create-mesh-node` is the one-command on-ramp for an *organisation* — it writes a charter, handshake, directory fragment and workflow, then verifies L2. This package scaffolds a single *agent*'s starting point inside (or beside) an org that has already done that. Running this one does not make an org mesh-conformant, and running that one does not give you an agent's own package.
- **Not a hosting platform.** The scaffold is files on disk. Where they run, and whether they are ever deployed, is entirely the adopter's decision.
- **Not adopted.** As at this commit, nothing has been generated by it, because there is nothing here yet to generate anything.

## Status

**The generator is not here yet.** It is Apache-2.0 today; carrying the
package out of the monorepo it was written in (`packages/create-mesh-agent`
in `FlashyLabs/flashyos`), *with its real commit history*, is a deliberate
operation rather than a copy — a chain of title that begins on the day
somebody remembered to copy the files is not a chain of title. Until that
runs, this repository is the licence, the security policy and the direction.

## Contributing

**The most useful thing you can send is a scaffold that fails in a real project.** A generator that only ever runs against its own fixtures has never met the directory names, the existing `package.json` fields, or the half-finished `.gitignore` a real adopter actually has.

Sign-off rather than a copyright assignment — see [CONTRIBUTING.md](CONTRIBUTING.md). There is no CLA.
